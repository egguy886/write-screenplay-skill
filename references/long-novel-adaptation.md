# 长篇小说改编引擎（Long-Novel Adaptation Engine）

> 适用：原著 ≥ 20 章，或目标 ≥ 30 集。目标：把几十万字的长篇**压进固定集数（默认 ≤ 60 集）**，每一集都像小说章节一样**停在钩子上**。
> 核心思想：**先规划、后写作。** 单集写作（SKILL.md 的四步转译法）只是最后一步；长篇改编 80% 的质量取决于前面的"压缩决策 + 分集大纲"。

---

## 零、为什么不能一章一集

| 误区 | 事实 |
| :--- | :--- |
| 一章一集最忠实原著 | 一章 1,500–1,800 英文词，对白约 400–600 词；一集 2 分钟只装得下 **150–220 词对白**。一章一集照样要砍掉六成以上，忠实只是幻觉。 |
| 章节钩子可以直接当集尾钩子 | 章节按"阅读 7 分钟"设计，一集只有 1.5–2 分钟；大量章节是心理/过渡，拍出来没有可见冲突。 |
| 集数越多越赚 | 出海平台（ReelShort / DramaBox / ShortMax）言情主流 60–90 集；超过 100 集流失严重，制作量线性翻倍。 |

**结论：** 集数由"可拍的强节拍数量"决定，不由章节数决定。默认上限 60 集（两季可到 80）。

---

## 一、六步流程（L0–L6）

产物统一放在小说目录下的 `adaptation/`。每一步有**门禁**，不过门禁不进下一步。

| 步 | 产物 | 工具 | 门禁 |
| :--- | :--- | :--- | :--- |
| L0 立项参数 | `adaptation/00_改编参数.md` | 模板 | 用户确认：集数上限、单集时长、平台、尺度、V.O. 用量、要删的番外 |
| L1 全书消化 | `adaptation/chapters.json` + `01_章节索引.md` | `scripts/chapter_index.py` 先扫字数/对白比/短信量/章尾段，Agent 按卷填写节拍卡，`scripts/merge_cards.py` 合并 | 每章都有 summary / function / keep / hook_strength；**已核对正文章尾** |
| L2 压缩决策 | `adaptation/02_压缩决策.md` | 压缩工具箱（本文第三节） | 每条支线、每个配角、每个场景都有"保留/合并/删除/浓缩"结论 |
| L3 集数预算 | `adaptation/arcs.json` → `budget.md` | `scripts/episode_budget.py` | 总集数 ≤ 上限；付费点、中点、高潮落在规定区间 |
| L4 分集大纲 | `adaptation/episodes.json` → `04_分集大纲.md` | `scripts/outline_check.py` | ❌ 清零；**用户逐集审过**（最重要的一关） |
| L5 逐集写作 | `adaptation/scripts/E001_xxx.md` … | SKILL.md 四步转译 + `templates/adaptation/episode_template.md` | `scripts/script_lint.py` ❌ 清零 |
| L6 审计与账本 | `adaptation/03_连续性账本.md` 每批更新 | 人工 + lint | 每写完一卷通读一遍；账本与剧本一致 |

**批量节奏：** L1 按卷读（一卷一批，可并行子代理）；L5 每批 5 集，写完一批跑 lint、更新账本，再写下一批。

## 二、L1 节拍卡：每章要提取什么

`chapter_index.py` 先给出客观数据（字数、对白词数、对白占比、章尾最后一段、配套复盘卡路径）。Agent 读原文（有复盘卡/摘要时先读卡，再抽查原文）后补齐：

| 字段 | 含义 | 取值 |
| :--- | :--- | :--- |
| `summary` | 一句话：谁做了什么，结果如何 | ≤ 40 字 |
| `beats` | 可拍的事件节拍（外部动作，不写心理） | 列表，每条 ≤ 25 字 |
| `function` | 这一章在全书里的作用 | `trigger` 触发 / `escalate` 升级 / `reveal` 揭示 / `twist` 反转 / `romance` 感情推进 / `payoff` 回收 / `setup` 埋伏笔 / `breather` 喘息 / `filler` 过渡 |
| `keep` | 压缩建议 | `core` 必保 / `merge` 合并 / `montage` 浓缩成蒙太奇 / `cut` 删 |
| `emotion` | 情绪强度 | 1–5 |
| `hook_strength` | 章尾钩子强度（拍出来是否仍然抓人） | 1–5 |
| `info_changes` | 信息差变化：谁新知道了什么 | 列表 |
| `props` | 本章出现/改变状态的关键道具 | 列表 |

**⚠ 以正文为准，不以细纲/复盘卡为准。** 原著常有"细纲 ≠ 成稿"：章尾钩子、出场人物、地点、甚至人物姓氏会和大纲不一致（实战中发现：同一人物三种姓氏、楼层前后矛盾、章尾落点改变）。节拍卡先用细纲/复盘卡起草，但**每一章必须核对正文的开头、中段、章尾**；集尾钩子一律取正文真实章尾；发现的矛盾记入 `02_压缩决策.md` 第 0 节"设定统一口径"。写 L5 时每集的来源章节仍要**通读正文**。

节拍卡太多时分卷写成 `adaptation/cards/vN.py`，用 `python3 scripts/merge_cards.py adaptation/chapters.json adaptation/cards/` 合并。

**可拍性速判：** 对白占比 < 15% 且 function 是 breather / filler 的章，几乎都是 `montage` 或 `cut` 候选。

## 三、L2 压缩工具箱（七种手法，按优先级）

1. **保（Keep）**：主线因果链、每一个反转和揭示、爽点兑现、伏笔的埋设与回收。判断标准：删掉它，后面会不会有一处看不懂或不解气？会 → 保。
2. **并场（Merge Scenes）**：两场戏功能相同（都是"男主试探、女主圆谎"）→ 合成一场，取两场里最好的台词和动作。
3. **并人（Merge Characters）**：功能重叠的配角合成一个（闺蜜 A + 室友 B → 一个闺蜜）。AI 出片时人越少，一致性越稳、资产越省。
4. **并景（Merge Locations）**：同类场景归并成少数固定主场景（办公室 / 公寓 / 门厅 / 车内…）。**AI 短剧主场景控制在 8–12 个。**
5. **三次法则（Rule of Three）**：同一类桥段（圆谎、差点穿帮、吃醋）全剧最多出现三次：建立 → 升级 → 兑现。第四次起删或合并。
6. **浓缩（Montage / Time Cut）**：日常甜宠、时间流逝、反复的消息往来 → 一组 3–5 个镜头的蒙太奇，或一串手机屏幕。
7. **前移/重排（Move Up）**：下一章的揭示/钩子挪到本集结尾；必要时用 **flash-forward 冷开场**（E01 前 5 秒先闪高潮画面再倒叙）。

**外化（Externalize）是压缩的配套：** 第一人称内心戏 → ① 手机屏幕文字（短信/聊天/转账/搜索记录）② 道具特写 ③ 动作与微表情 ④ 少量 V.O.（全集 V.O. ≤ 对白词数的 25%，只在不得不交代动机时用）。

**不能动的东西（红线）：** 原著设定的人物底线、尺度红线、成年线、同意原则、核心卖点（例如"他早就知道"的戏剧反讽）。写进 `00_改编参数.md`。

## 四、L3 集数预算：怎么把全书控制在 60 集内

### 1. 先算压缩比
`压缩比 = 进入正剧的章节数 ÷ 目标集数`。

| 压缩比 | 做法 |
| :--- | :--- |
| < 1.2 | 接近一章一集，注意注水；考虑减少集数 |
| 1.2–2.5 | 正常：每集 1–3 章，靠并场 + 浓缩 |
| 2.5–3.5 | 高压缩：必须删支线、大量蒙太奇 |
| > 3.5 | 超压缩：先砍整条支线/番外，否则每集都会变成剧情摘要 |

番外、平行世界、Bonus 章节默认**不进正剧**（可做特别篇）；终局打脸类番外可并入最后一集。

### 2. 按"卷的作用"分配，不平均切
`episode_budget.py` 按 **章节数 × 角色权重** 分配，再用最大余数法取整：

| 角色 role | 权重 | 说明 |
| :--- | :--- | :--- |
| `opening` 开局 | 1.25 | 前 10 集决定留存，钩子最密 |
| `build` 推进 | 1.0 | |
| `midpoint` 中点 | 1.25 | 大掉马/大反转 |
| `sweet` 甜宠/喘息 | 0.8 | 最该压缩 |
| `crisis` 危机/黑夜 | 1.25 | |
| `climax` 高潮 | 1.2 | |
| `resolution` 收尾 | 1.0 | |

预算出来后可以在 `arcs.json` 用 `fixed` 手动钉死某卷集数，其余自动重分。

### 3. 关键位置（60 集为例，按比例换算）
| 位置 | 集号 | 要求 |
| :--- | :--- | :--- |
| 付费墙 | E8–E12 | 一个**大钩子**（big），通常是开局卷的结尾 |
| 第一次关系质变 | E15–E22 | 让观众确信"这对能成" |
| 中点大反转 | E27–E33（45–55%） | 全剧最大的信息差爆破 |
| 至暗时刻 | E42–E50（70–83%） | 分离 / 背叛 / 逃离 |
| 高潮 | E50–E57 | 最大的公开对决或追逐 |
| 结局 | E58–E60 | 兑现 + 最后的爽点；可留一个续季小钩子 |

## 五、L4 分集大纲：每一集卡片

写在 `adaptation/episodes.json`（字段见 `templates/adaptation/episodes.example.json`），`outline_check.py` 校验并生成可读的 `04_分集大纲.md`。

每集必须回答：
1. **来源章节**（`source`："12-13"）——所有进入正剧的章节都要被覆盖，或在 `cut` 里写明删除理由。
2. **开场回钩（open_payoff）**：前 10 秒怎么接住上一集的钩子（兑现一半，留一半）。
3. **本集目标与阻碍（goal）**：主角这 2 分钟要拿到什么，谁拦着。
4. **中段转折（turn）**：第 40–80 秒发生了什么让局面变化。
5. **集尾钩子（end_hook）**：类型 + 强度 + 具体画面/台词（见 `episode-hook-system.md`）。
6. **场次（scenes）**：≤ 4 场；2 分钟的戏 2–3 场最舒服。
7. **信息差状态（info_state）**：此刻观众 / 女主 / 男主各自知道什么（戏剧反讽类故事必填）。

**切集原则：先找钩子点，再切集。** 章尾 `hook_strength ≥ 4` 的位置优先当集尾；两个强钩子之间内容太多就浓缩，太少就把下一个揭示前移。**不要按"每集固定 2 章"机械切。**

## 六、L5 单集内部结构（2 分钟 / 8 段 × 15 秒）

| 时间 | 段 | 内容 |
| :--- | :--- | :--- |
| 0–10 秒 | 1 | **回钩**：直接接上集最后一个画面或兑现上集悬念的一半 |
| 10–40 秒 | 2–3 | 本集目标 + 阻碍，信息量最密 |
| 40–80 秒 | 4–5 | **转折**：新信息/新压力/关系变化 |
| 80–110 秒 | 6–7 | 加压：把主角逼到要做选择 |
| 110–120 秒 | 8 | **集尾钩子**：停在"答案出口前/动作落地前"，最后 1–1.5 秒是有内容的停留画面 |

**对白预算：** 120 秒 ≈ 150–220 个英文词（含 V.O.）；屏幕文字另计但每块 ≤ 4 行。超了就删台词，不要加速。

## 七、L6 连续性账本（每批 5 集更新一次）

`templates/adaptation/03_连续性账本.md` 四张表：
1. **信息差表**：秘密 × 观众/主角/对手 什么时候知道（第几集）。
2. **道具生命周期**：道具首次出现 → 状态变化 → 回收集号。
3. **关系状态线**：每集结束时两人关系处于哪一档。
4. **造型/场景状态**：服装、伤、物品摆放的变化（下游 AI 出片要锁参考图）。

原著已有伏笔/道具追踪表的，直接导入，不要重做。

## 八、常见失败与修正

| 症状 | 原因 | 修正 |
| :--- | :--- | :--- |
| 每集像剧情摘要 | 压缩比过高还硬塞 | 删支线；一集只讲一件事 |
| 集尾很平 | 按章数机械切集 | 回到 L4，按钩子点重切 |
| 观众看不懂动机 | 内心戏没外化 | 加手机屏幕/道具；最后才用 V.O. |
| 中段拖 | sweet 卷集数给多了 | 压到权重 0.8 以下，用蒙太奇 |
| 前后矛盾 | 没有账本 | 每批更新账本，写下一批前先读 |
| 钩子雷同 | 同类型连用 | 同类型不连续超过 2 集（outline_check 会拦） |
